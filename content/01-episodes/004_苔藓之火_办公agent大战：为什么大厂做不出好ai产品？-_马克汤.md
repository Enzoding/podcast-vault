# 办公Agent大战：为什么大厂做不出好AI产品？——苔藓之火EP46对话马克汤


## 1. 一句话概括

本节目聚焦中国大厂在AI办公Agent赛道（以腾讯Workbody、字节豆包/飞书、阿里钉钉等为代表）的激烈竞争与组织困境，深入剖析了“为何手握重金的大厂至今做不出让人耳目一新的AI原生应用”这一核心问题，并对海外Google、微软、苹果、Meta的表现进行对比，最终落脚于AI替代白领的终局猜想与未来渠道之争。

## 3. 章节要点

### 3.1 电梯广告里的“办公AI”战争信号

主持人Raymond从一次按摩途中看到的分众传媒电梯广告切入，引出当下办公AI产品的广告投放热潮。他说分众传媒是中国商业战争的第一线见证者——电梯之前告诉他世界杯买炸鸡、用阿康看病、免费拿外卖奶茶，现在又告诉他用Workbody写脚本、画图、给老板写报告。马克汤补充指出，不仅电梯广告，机场广告也从云厂商（百度云、火山云）下放到应用层，地铁里也有百度办公类应用广告，这些投放极贵，普通创业公司根本没有资源做。Raymond举了一个具体案例：他的一位网红朋友一个月能接四条不同的Body（Workbody）广告，单条成本十几万，每月仅这一项就能赚约6万元，广告加载率高达25%。马克汤还提到，2024年投得最凶的是Kimi和豆包这类Chatbot产品，但至今Chatbot仍未找到合适的变现方式，CPA获客成本越投越高、账越来越难算。

### 3.2 什么是“AI原生”产品？大厂产品为何“为了AI而AI”

马克汤提出，一个好的AI产品应当是用AI解决过去无法解决的问题，或将效率放大到无穷大，而不是把原来能做的事情做得快一点、做得“花哨”一些。他批评很多大厂产品硬把GUI（图形交互界面）改成LUI（语言交互界面），强制用户通过对话框输入才能启动功能，这种做法“有点反人性”，这正是小红书上很多人批评“为了AI而AI”的根源。他认为，大厂目前在AI产品上已有一定声量——豆包月活奔着10亿去、Google Gemini也接近10亿、Workbody月活超过两三千万，留存也出现了，但本质上没有看到一个能让大家耳目一新的、颠覆认知的AI时代Super App。

### 3.3 大厂通病①：OKR拆解与“局部理性”

马克汤系统阐述了“大公司病”的成因。他提到今年轰动一时的钉钉内部吐槽帖——钉钉被曝搞毫无人性的加班制度，面试要先往家里拉5个新用户才能进入下一轮，第二轮还要通过向5个人收集反馈来给产品提需求，因为要背活跃指标。他指出这背后的结构性问题是任务拆解：大公司自上而下定义任务（KPI/OKR），任务被无限拆解到子部门、子团队，导致每个部门都在做自己定义下“正确”的事情——算法同学只关心把回答准确率提升到多少、多轮对话轮次提升到多少，不关心用户实际感知；产品侧、运营增长侧、法务侧也是如此——最终各环节产出合在一起偏离了最初目标。他用“5000个优秀人组成的公司产能肯定不是5000乘以一个人的产能”来说明组织效能折损的必然性。

### 3.4 大厂通病②：内部赛马、利益博弈与“搬起石头砸自己的脚”

Raymond补充了两个案例。第一个是晚点报道的姚棐语“空降”腾讯拯救混元的300天，核心挑战不是模型训练本身（腾讯不缺资源），而是如何在不同部门、不同leader之间理顺利益关系，让所有人的利益逐渐倾向一致，同时获得总办赋予的足够信任和权威——这个“外来的医生一个一个摘掉陈年老病”的过程才是关键。第二个案例是玉伯（语雀创始人）在阿里做语雀时，阿里内部有语雀、钉钉文档、阿里文档三个部门并存，先是A要吃B、B要吃C，后又说都不吃，反复折腾最终没合并，玉伯觉得在大厂做这种事不可能，最终选择离开阿里自己创业。马克汤补充说，即使有想法，走大厂创新评审会需要准备PPT论证市场大小、用户预期、商业化增长、拉新渠道等太多问题，让创新者动力薄弱。他还指出成熟公司“搬起石头砸自己的脚”的困境——旧业务太赚钱（抖音是印钞机、天猫天天贡献大量收入），新业务是用来替代老业务的，投入决心自然不够。

### 3.5 组织解法对比：字节Flow的独立模式 vs 阿里ATH的CEO直管

字节在2024年成立了Flow部门，由Musical.ly创始人Alex Zhu领导（产品经理出身、有产品嗅觉），下设Seed（字节所有AI大模型部门，含语音、文本、视频，C-Dance、C-Dream都是这个部门做的）。Flow与抖音、番茄、今日头条完全拆开，不是旧业务的附属品，拥有独立期权（独立定价）、相对独立的运行状态。与之对比，阿里成立了ATH（Alibaba Token Hub），管Token从模型生产到供给到应用下放的全链条，事业群老板是吴妈（蔡崇信）本人——CEO直接管。马克汤认为这体现了两种组织形态的差异：字节倾向于建立完全独立的新组织，阿里倾向于一号位亲自挂帅来调配资源。他还提到雷军给小米大模型团队（负责人罗夫利，原DeepSeek模型负责人）的放权式管理——不给查岗、不问数据，全靠团队自驱。字节内部“亲兄弟明算账”的机制也很关键：飞书调用火山引擎模型内部结算不给折扣，反馈数据可以打包卖给模型方，这鼓励各方把事情打磨得更精细，避免混水摸鱼算糊涂账。

### 3.6 飞书的特别之处

飞书最初是字节内部一个十人的内部通讯项目，没有KPI、没有商业化压力，先解决自己的问题，再把字节内部先进组织的管理经验、沟通机制、文档系统、审核机制、法务合规全部塞进产品。现在飞书已有几千人，经历过一波大幅裁员（觉得这么多人没有这么多产出），但组织基因仍然是内部自我催生的产品。同时飞书与Flow的关系是内部结算关系而非合作绑定关系——作为Seed模型的调用方，但没有任何折扣，这促使飞书把产品打磨得更加精细。

### 3.7 海外篇①：Google为什么稳住了？

Google是大厂中AI应用做得相对成功的一家。马克汤指出，此前市场担心AI搜索会替代传统搜索冲击广告收入，但最近几期财报正伪了这一担忧——Google的广告收入没有下降，反而增加了。两位主播也坦诚自己用Google搜索的query深度和数量大幅下降（从“想找什么数据”转为“找网页或图片”），但搜索市场份额没有出现预期中的大跌，Gemini的月活持续增长、接近10亿，且主要是从ChatGPT网页端抢的量。去年年底Gemini 3发布后，前端能力极强（小红书上大量人用Gemini画原型），Google内部有一套完整的应用组合——Anti-gravity写代码、AI Lab画原型交互设计、AI Scratch画UI/UX稿件。但今年声音变弱了，“基模的能力也不是特别的出众”。

### 3.8 海外篇②：Meta无亮点，微软输在生态与“可替代性”

Meta几乎没有拿得出手的AI应用，之前要出租算力（收购Minus后也没有学到什么内化成自己产品），Facebook和WhatsApp拥有巨大潜力但都未在AI上发力。微软在应用端机会渺茫：一是Windows系统在AI时代不友好，搞AI的人基本都买Mac（统一内存架构，不需要数据搬运，能耗更好，新MacBook Pro轻度办公能用20小时；iPhone上的AI应用也都先支持Mac芯片）；二是Office套件的“可替代性”——未来为什么还需要PPT、Excel和Word？Google云文档和飞书文档已做得特别好且集成更好，Office Copilot如果没有跟上，用户完全可以用封装更多AI成熟能力的产品替代。微软最值钱的部分是OpenAI股权，本质转向基础设施（Azure云、FDE），帮更多企业接上AI做好组织转型。

### 3.9 苹果为什么被市场奖励？

苹果几乎不参与AI军备竞赛、不烧Capex，股价却创了新高。马克汤将其归结为三点：第一，Mac硬件生态优势强，统一内存架构在AI时代碾压Windows，市占率逐步扩大；第二，苹果能像“消费电子界的麦当劳”一样把成本涨价摊给用户，证明稀缺性价值；第三，Apple Intelligence仍有机会——苹果推出了协议级别的组件，让OS系统能调用第三方应用的接口，就像微信提供给小程序开发者的SDK能让微信作为某种OS调用小程序接口一样，这是一个OS级别Agent的雏形。尽管Vision Pro算一个比较失败的产品（售价高、出货量极低），但苹果在AI终端的入口优势依然明显。

### 3.10 未来入口之争：OS Agent vs Super App Agent

马克汤清晰地梳理了两个竞争层级：一是OS Agent——用户跟硬件（手机）说话，硬件把任务派给APP（如Siri、小艺、理想同学）；二是Super App Agent——用户跟超级APP说话，APP把任务派给APP内的小程序（如微信AI点外卖、支付宝查账单）。这场仗怎么打取决于两个要素：体验（跟硬件说话可以在熄屏状态唤起，天然比打开微信再说话更丝滑）和数据（谁能拿到用户最完整的上下文）。OS Agent掌握全局context，各APP只能拿到拆分后的局部任务（外卖APP不知道你有吃麻辣烫的习惯，打车APP不知道你喜欢录播客），这导致下层APP逐渐被压缩成“厨房里做菜的角色”甚至失去用户ID。但问题是：如果微信不给权限不接，硬件Agent能否通过computer use（视觉操作）绕过限制？答案是技术上可行（只需要屏幕共享权限），大厂们都不愿意被当成被统一调度的工具。

### 3.11 “预装应用”战争卷土重来，渠道决定命脉

马克汤预言：未来竞争最终就是渠道之争、流量之争。因为AI让APP供给变成无限供给——任何人只要有想法，用Codex或Claude就能搓出一个好应用——最终谁把握流量和预装，谁就把握命脉。手机厂商和APP之间的“排他协议”“预装买断”叙事将卷土重来，类似于2010-2014年中国APP预装乱象（店员帮阿姨一次性装八个办公软件拿回扣）。APP希望被OS的Agent多调用，就买预装；甚至字节可能说“别装Workbody，装我的办公软件”。Raymond开玩笑问该买什么股票（顺宇光学等），两位主播也承认这一趋势尚需探讨具体标的。

### 3.12 AI替代人力的进度条：从赋能到替代

马克汤认为12个月内办公Agent必将从“赋能”进入“替代”阶段。论据是：中美模型差距已从18个月缩至半年以内——马上要发的GLM 5.3、智谱的新模型、千问的新型小模型，基本都到了此前被认为“足够能用”的Opus 4.8水平。美国裁员已真实发生（微软、Meta、Amazon都在裁），且会“裁着裁着上瘾”加速推进——人还要扮演审核者和代码检测者，但随着这些工作也被替代，更多人就不需要了。中国裁员是变相裁员：大厂流动性强，原来走两个人补两个人，现在是“走得够人我才给你补人”（走五个人补一个人），员工数量可以在财报里观察。马克汤直言：“一个老师傅带五个Agent，比五个老师傅带五个应届毕业生厉害多了。”知识工作者的资产在电脑里，数据被采样、蒸馏后，人就不再被需要——但Token Maxing（公司让员工疯狂用AI探索）的窗口期已结束，老板会用投入产出比衡量，谁用Agent跑了几百亿Token却没业绩，谁就会被发现。

### 3.13 评估标准：产品如何被衡量

字节的豆包配了至少二三十个专门做评测的产品经理，不干别的，就是定义评测标准、扫query、看结果。除了日活月活等结果指标，还要看过程指标：平均对话轮次、多轮对话中用户负面情绪（“你又忘了”“这不刚说过吗”属于亮红灯的负面信号）、留存（今问明不问）、预期query数中有多少流转到本应用——这些是传统互联网产品评估逻辑的延续，本质上没有差异，只是权重变了：以前要求用户疯狂花时间，现在可以用一万个人每人收一万块钱做出一个亿营收，不需要服务十亿人每人收一毛。


## 4. 核心观点与论证

1. **大厂做不出好AI产品是组织问题而非技术问题。** 大公司病（OKR拆解导致局部理性）、内部赛马（“你做了我也做一个”最终合并）、利益博弈（动旧业务蛋糕难以下决心搬石头砸自己脚）、层层审批耗散创新动力（前期就要论证市场规模、增长渠道），这些因素共同扼杀了AI原生产品的诞生空间。字节Flow的相对成功恰恰证明：独立组织+独立期权+内部结算+不耦合旧业务是更有效的解法。

2. **“AI原生产品”必须解决过去解决不了的问题，而不是旧功能的AI化包装。** 把GUI硬改成LUI是反人性的“为了AI而AI”；只有重新定义由技术才能解决的问题（效率被放大到无穷大），才是真正的AI原生。当前大厂产品大多只是让用户做得快一点、做得“fancy”一些，没有本质创新。

3. **大模型时代迁移成本被抹平，模型忠诚度归零，竞争焦点从技术转向渠道。** Claude和Codex用户能一键无痛迁移（本地记忆和MCPs技能自动同步），国内Workbody接开源模型用户可选DeepSeek、GLM等——所以没有人为混元而用Workbody。谁能把握流量和预装入口、谁能在OS层拿到用户完整上下文，谁才是最终赢家。

4. **AI对白领的替代已经进入落地阶段，12个月内将加速。** 中美模型差距缩小到半年内，模型能力已越过“足够能用”的线（Opus 4.8级别），美国裁员已在大厂真实发生且将加速，中国以“隐性的变相裁员”（走五人才补一人）同步推进。“蒸馏”知识工作者后，一人配多个Agent即可完成原三人工作，且这是一把手工程——只有付工资的人能快速理解这个逻辑。

5. **未来入口之争是OS Agent与Super App Agent的战争，而OS层暂时占优。** 硬件Agent可以熄屏唤起、更丝滑、掌握全局上下文（各APP只获取拆分后的局部任务），可以通过computer use越过APP不愿开放接口的壁垒；但前提是预装与排他协议将成为渠道命脉，手机厂商与超级APP将围绕“跟用户直接建立连接的位置”展开激烈争夺。

## 6. 金句

1. **“局部理性，就是每个部门都在做自己定义下正确的事情，但最终结合产出就偏离了最初的目标。”** ——马克汤解释大公司病（OKR拆解）的结构性成因：算法只关心准确率，产品只关心指标，合在一起用户感知是薄弱的。

2. **“模型的忠诚度是零，谁强用谁的。迁移成本一旦被抹平，用户随时可以走。”** ——马克汤论述大模型时代用户没有品牌忠诚——Claude用户迁移到Codex时记忆和MCPs技能自动无痛同步（数据留在本地），说明迁移成本决定用户粘性。

3. **“搬起石头砸自己的脚——旧业务太赚钱，新业务就下不了决心砸资源。”** ——马克汤解释大厂即使发现了AI方向，因新业务势必要替代老业务收入，内部决策动力不足。

4. **“未来的竞争，最终就是渠道之争。谁把握流量和预装，谁就把握AI应用的命脉。”** ——马克汤预判预装应用战争将卷土重来，APP成为无限供给之后，渠道变得更加稀缺。

5. **“一个老师傅带五个Agent，比五个老师傅带五个应届毕业生厉害多了。”** ——马克汤描述AI替代白领的现实效率逻辑，说明为何裁员加速不可逆。

6. **“数据被采样到了之后，然后蒸馏完了，然后人就不再被需要了。”** ——马克汤描述知识工作者被AI替代的机制：资产在电脑里，被蒸馏后即被替代。


## 7. 延伸思考

1. **OS Agent与Super App Agent的战争将如何收场？** 手机厂商掌握硬件入口（熄屏可唤起、全局上下文），但超级APP（微信/支付宝）拥有海量历史关系数据与小程序生态。如果微信坚决不开放接口且不允许computer use越权操作，OS Agent能走多远？是否会出现“你的手机能操作一切，唯独进不了微信”的僵局？

2. **“蒸馏掉”白领之后的社会结构将如何演变？** 当知识工作者的产出能力被“一人配多Agent”替代，企业端的用人逻辑彻底改变——应届毕业生就业将面临何种冲击？中美之间“显性裁员vs隐性变相裁员”的差距是否会因全球竞争压力被迫拉平？这是否意味着社会需要重新设计教育体系与分配机制？

3. **AI产品的终极评估标准是否应超越日活月活与商业化？** 如果“只服务一万人每人收一万块”成为可行商业模式（一万个人每人一万块钱就是一个亿营收），那么AI产品经理的核心能力是否正在从“获取海量用户”转向“锁定高价值场景”？这对创业公司的产品选择与融资逻辑会产生什么影响？
